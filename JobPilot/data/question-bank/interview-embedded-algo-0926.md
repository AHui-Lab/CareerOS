## 第1题（C语言 · 结构体指针与 sizeof）

**题目：** 给出一个结构体，里面定义了很多变量，并在结构体结尾用 `*p` 定义了这个结构体指针（形如 `struct S { ... } *p;`）。问：`sizeof(p)` 是多少？`p++` 会移动多少？

**考察点：**
- 是否分清"指针本身的大小"与"指向类型的大小"
- `sizeof(p)` vs `sizeof(*p)` 的本质差异
- 指针算术与类型大小的绑定关系

**回答建议（嵌入式工程师角度）：**

`struct S { ... } *p;` 这里 `p` 是 **指向结构体的指针**，不是结构体变量。

1. **`sizeof(p)` = 指针大小**，与结构体有多少成员无关：32 位平台是 4 字节，64 位平台是 8 字节。很多人误答成结构体的大小——注意 `sizeof(p)` 看的是 p 这个"变量"的类型，即 `struct S *`。
2. **`sizeof(*p)` = 结构体大小**：`*p` 解引用后是 `struct S`，大小等于各成员按对齐规则排列后的总大小（注意字节对齐/填充，可用 `offsetof` 验证）。
3. **`p++` 移动 `sizeof(struct S)` 字节**：指针算术以"指向类型的大小"为步长。结构体实际占 28 字节，`p++` 就 +28，指向下一个结构体；而不是 +1 字节或 +4 字节。

加分句：「所以遍历结构体数组时，`p++` 正好跨过一个元素；如果想按字节步进，需要 `(char*)p` 强转」。

**HR/面试官视角评价：**
- ✅ 加分信号：直接区分 `sizeof(p)` 与 `sizeof(*p)`，并指出对齐填充对结构体大小的影响
- ❌ 减分信号：答"sizeof(p) 就是结构体大小"——把指针和对象混为一谈，C 功底不扎实

## 第2题（嵌入式 · 中断响应过程与 ISR 书写规范）

**题目：** 请描述一次中断的完整处理过程。又给出一段中断服务函数（返回值定义成了 `double`，函数体内是 `area = PI * r * r; printf(area); return area;`），问这段代码有什么错误？

**考察点：**
- 中断从触发到返回的完整链路（硬件 → 上下文保存 → ISR → 恢复）
- ISR 的书写规范：返回类型、可重入性、阻塞调用、浮点、执行时长
- 能否把"规范"讲成"为什么"，而不是背教条

**回答建议（嵌入式工程师角度）：**

**一、中断处理完整过程：**

1. **中断请求**：外设（定时器/UART/GPIO 等）置中断标志，向 NVIC/中断控制器发出 IRQ。
2. **响应与判优**：中断控制器按优先级裁决；若该中断使能且优先级高于当前屏蔽位，CPU 在当前指令执行完后响应（不打断指令中间）。
3. **硬件压栈（上下文保存）**：CPU 自动把返回地址（PC/xPSR，ARM 上还有 LR/R0-R3/R12 等）压入当前栈（或 MSP），跳转到中断向量表对应的入口。
4. **进入 ISR**：执行用户编写的中断服务函数；编译器生成的 prologue 可能再保存用到的其余寄存器。
5. **中断服务体**：做最少的必要工作——清标志、搬数据、发信号量/置事件；耗时逻辑交给主循环或任务。
6. **返回与出栈**：执行中断返回指令（如 `BX LR` 走 EXC_RETURN），硬件自动恢复寄存器，回到被中断的上下文继续执行。

注意：同级/低级中断默认被屏蔽（可配抢占）；ISR 里再开中断要注意嵌套与栈溢出。

**二、示例代码的问题（返回类型 `double`，`area = PI*r*r; printf(area); return area;`）：**

1. **返回类型错误**：中断服务函数应是 `void`（或厂商规定的 `void XXX_IRQHandler(void)`）。中断靠硬件出栈返回现场，**没有调用者接收返回值**，`double` 返回毫无意义，还会迫使编译器处理浮点返回约定。
2. **ISR 中调用 printf**：printf 有锁、可阻塞、不可重入，耗时长（尤其重定向到 UART），在 ISR 里调用会导致中断延迟飙升、优先级反转，甚至死锁；打印应放到主循环/低优先级任务。
3. **返回 area 语义错误**：即使普通函数，返回计算结果应通过参数/全局/消息传递；ISR 更应如此。
4. **浮点运算**：ISR 里做 `PI*r*r` 需确认 FPU 上下文保存与是否允许；部分 MCU 默认不保存 FPU 寄存器，嵌套后会踩坏浮点现场；且浮点运算本身偏慢，不宜放 ISR。
5. **执行体过长**：ISR 应"短平快"，计算、格式化、打印都应外移。

正确做法：ISR 内只置标志或通过环形缓冲/信号量通知任务，`area` 的计算与 printf 放到任务/主循环中执行。

**HR/面试官视角评价：**
- ✅ 加分信号：先答流程再挑错；挑错能按"返回类型 → 可重入/阻塞 → 浮点 → 时长"的优先级讲，并给出改造方案
- ❌ 减分信号：中断流程只能说出"进中断、出中断"；只发现 printf 问题，漏掉返回类型/返回值语义

## 第3题（项目 · 嵌入式与算法结合）

**题目：** 结合你做过的项目，谈谈嵌入式方面的实现与其中用到的算法。（开放题）

**考察点：**
- 项目真实性：能否讲清自己负责的模块、选型理由、调试手段
- 嵌入式素养：实时性、功耗、资源受限下的取舍
- 算法落地能力：理论到工程的差距（定点化、内存、时延）

**回答建议（嵌入式工程师角度）：**

按"背景 → 我的职责 → 嵌入式实现要点 → 算法要点 → 结果/反思"五段讲：

1. **背景与职责**：一句话说清产品场景和自己负责的模块（驱动/固件/算法移植）。
2. **嵌入式实现**：选型（MCU/传感器/通信接口 I2C/SPI/UART）、中断与任务划分（裸机状态机或 RTOS）、关键约束（功耗、采样率、时延预算）、调试手段（示波器/逻辑分析仪/日志/断点）。
3. **算法落地**：算法是什么（滤波/定位/识别），资源占用（Flash/RAM/CPU%），是否做定点化或查表加速，边界条件与鲁棒性处理。
4. **结果**：量化指标（精度/时延/功耗/良率）。
5. **反思**：踩过的坑与改进，如中断里做重活、时序不达标、传感器漂移等。

**HR/面试官视角评价：**
- ✅ 加分信号：有量化结果、能讲"为什么这样选型"、主动说踩坑与解决
- ❌ 减分信号：只报功能流水账，说不清时延/资源/功耗任何一个数字

## 第4题（算法 · KF 与 EKF 的区别）

**题目：** EKF（扩展卡尔曼滤波）和普通 KF（卡尔曼滤波）有什么区别？

**考察点：**
- 是否理解 KF 的线性/高斯假设
- EKF 的线性化（Jacobian）本质
- 工程选型：什么时候必须用 EKF

**回答建议（嵌入式/算法工程师角度）：**

1. **模型假设不同**：标准 KF 要求状态方程和观测方程都是**线性**的（x_k = F x + B u + w，z = H x + v），噪声为高斯；EKF 允许**非线性**的状态转移 f(·) 和观测 h(·)。
2. **处理方式不同**：KF 直接用 F/H 做预测更新；EKF 在当前估计点对 f、h 做一阶 Taylor 展开，用 **Jacobian 矩阵 F=∂f/∂x、H=∂h/∂x** 代替，之后流程与 KF 相同（预测 → 卡尔曼增益 → 更新）。
3. **精度与稳定性**：EKF 是近似，线性化误差会导致次优甚至发散，对初值敏感；KF 在线性高斯下是最优估计。
4. **工程选型**：目标跟踪、IMU/轮速航位推算、GPS/INS 组合导航等模型天然非线性（三角函数、角度、距离倒数），必须 EKF；线性系统（如简单一维跟踪）用 KF 即可，计算更省——对 MCU 更友好。也可提 UKF（无迹卡尔曼，用 sigma 点避免求 Jacobian）作为对比，显示视野。

一句话总结：**EKF = 把非线性问题局部线性化后再套用 KF；区别在于线性化与 Jacobian，代价是近似误差与更高的计算量。**

**HR/面试官视角评价：**
- ✅ 加分信号：点出 Jacobian/一阶 Taylor 是核心，并结合自身项目（定位/IMU）说何时用 EKF
- ❌ 减分信号：只说"EKF 更复杂/更准"，讲不出线性化这一层
