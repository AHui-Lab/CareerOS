# CareerOS 全流程优化方案

日期：2026-09-24。范围：JobPilot、CareerVault 与浏览器助手。本文把“用户要做什么、系统怎么回应、失败后怎么继续”作为每条流程的基本单位。

## 产品目标与验收口径

- 新用户能在 5 分钟内完成第一条经历和第一条岗位的录入，并知道下一步在哪里。
- 导入岗位前展示解析字段；同一链接再次导入时明确提示更新，保留投递状态。
- 首页优先展示未来 7 天的笔试、面试、截止时间和用户写下的下一步行动。
- 简历生成记录来源、所选经历、目标岗位和版本时间；旧预览不得被误认为当前输入的实时结果。
- 插件填表默认保留招聘网站已有输入；必须明确选择简历版本；敏感字段逐次授权；薪资、健康、调剂等判断题始终留给用户。
- 每个写入流程需有成功、失败、重复、取消四种可理解的反馈。

## 逐流程设计

| 流程 | 用户步骤与系统反馈 | 本轮落地 | 下一项缺口或验收重点 |
|---|---|---|---|
| 安装与启动 | 安装依赖 → 启动两个服务 → 页面展示连接状态 | 保留统一入口；首页继续显示经历服务状态 | 首次启动应展示两服务诊断及修复按钮；断连时明确哪些功能仍可用 |
| 初次建档 | 填基础资料 → 建教育和经历 → 标记可用于简历 | 维持 CareerVault 为事实来源 | 增加首用任务清单和资料完整度；消除 JobPilot 旧经历库与 CareerVault 的双重入口 |
| 插件采集岗位 | 打开招聘详情 → 识别公司、岗位、地点、JD → 人工核对 → 确认导入 | 插件增加解析预览和字段修正；优先读取页面主体与 JobPosting | 对北森、Moka、牛客各建真实页面样本；登录页、职位列表页提示进入具体岗位 |
| 网页导入岗位 | 粘贴链接或文字 → 预览解析 → 修改字段 → 确认保存 | 新增预览接口、核对页和登录页提示 | 链接抓取失败时保留输入并一键切换到文字模式；记录解析质量反馈 |
| 重复岗位 | 检测同一链接 → 告知已有记录 → 人工确认更新 | 更新时保留投递状态和人工核对 JD | 对无链接的文本导入增加相似岗位提示；明确哪些字段更新、哪些字段保留 |
| 岗位推进 | 核对 JD → 分类 → 标记状态 → 写下一步和计划日期 | 新增行动字段、优先排序、“做简历”入口 | 增加状态变更历史；批量清理已结束岗位；对逾期行动提供完成或延期操作 |
| 日历与待办 | 记录笔面试、跟进、截止 → 首页查看近期任务 → 点开对应岗位或日程 | 首页先显示可执行事项，月历默认收起；行动日期进入待办 | 行动与日程应可互相转换；同一岗位的重复提醒应合并 |
| 邮件跟踪 | 配 IMAP → 检查新邮件 → 人工确认 → 关联岗位或忽略 | 忽略邮件可恢复为待确认；首页提示待确认数量 | 邮件与岗位可给出候选匹配及理由，但关联必须人工确认；增加配置连接测试 |
| 经历与证据 | 建项目或实习 → 写个人贡献与结果 → 上传佐证 → 标记 Resume Ready | 保持事实库及佐证流程 | 经历卡应显示资料完整度、证据数和是否可用于简历；嵌入页面需消除双层滚动 |
| JD 匹配 | 选择岗位 → 读取 JD → 推荐相关经历 → 用户增删选择 | 岗位列表可直达简历页；目标切回手填时清空旧岗位字段 | 给每条推荐显示命中要求和缺失要求；JD 改动后明确使旧推荐失效 |
| 简历生成与版本 | 确认所选经历 → 生成 → 预览 → 下载 PDF/DOCX | 生成前检查目标岗位、JD 和已选经历；预览标明目标岗位、生成时间和历史版本属性；隐藏原始经历 ID | 增加版本差异对比；逐条检查缺失的成果数字和证据 |
| 插件辅助填表 | 选择资料版本 → 逐字段填写 → 查看结果 → 用户检查并提交 | 显式选择版本；默认不覆盖已有内容；敏感授权收窄；显示字段明细并可撤销本次已填字段；新增经历行单独授权；不自动提交 | 撤销不自动删除动态新增行；站点适配仍需固定样本回归 |
| 面试与笔试 | 关联岗位 → 按场次或试卷录题 → 独立作答 → 看解析 → 复盘 | 现有分区和题目记录流程可用 | 从岗位详情一键建立面试场次；显示未复盘题目及下次复习日期 |
| 私密资料 | 填证件、联系方式、照片 → 本机保存 → 必要时填表 | 证件号码默认遮挡，可按需显示 | 将身份资料与普通设置分区；提供“本次插件使用了哪些字段”的可见记录 |
| 备份与同步 | 本机备份 → 检查远端 → 确认接受或提交 → 回滚 | 保留已有确认和回滚机制 | 增加备份列表及单个备份恢复预览；同步前显示本地和远端时间、内容数量差异 |
| 移动端 | 打开页面 → 导航 → 查看岗位和待办 | 导航压缩为一行可横向滚动，首屏更快进入内容 | 逐页验收 390px 和 768px 宽度，尤其经历 iframe、长表单与对话框 |

## 下一阶段优先级

1. **P0：岗位导入和填表样本回归。**准备北森、Moka、牛客及普通招聘页的脱敏 HTML 样本，逐个验证公司、岗位、JD、截止时间和字段匹配。
2. **P1：CareerVault 嵌入与资料入口统一。**现在仍有 iframe 双层滚动和旧经历入口，容易误判事实来源。
3. **P1：简历内容核查。**在已有的目标/JD/经历检查之外，逐条提示缺少的教育时间、成果数字和证据，避免直接生成看似完整的简历。
4. **P1：备份恢复预览与首用引导。**让用户能看懂数据会如何变化，再执行恢复或同步。

## 回归场景

1. 同一链接导入两次：第二次显示已有记录；确认更新后，状态和已投递时间不丢失。
2. 登录页或招聘首页：提示识别不可靠，仍允许人工补齐后保存。
3. 岗位写入下一步及日期：列表可见，临近或逾期时首页可点回岗位。
4. 改变简历目标岗位：右侧旧预览保持明确的历史版本标签。
5. 插件选“仅基础资料”：不得暗中使用最新的不相关岗位简历。
6. 插件填表：默认不覆盖现有值；允许敏感字段后仍不填写薪资、调剂、健康等判断题；绝不点击提交。
7. 邮件忽略后：可从“已忽略”恢复到“待确认”。
