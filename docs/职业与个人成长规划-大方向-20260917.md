# 职业与个人成长规划（大方向版）

> 生成日期：2026-09-17
> 依据：已核实的简历素材（STM32 全链路毕设、BLE/计量院实习、microLED 晶圆检测课题、专利）+ 2026 求职咨询记录 + 2026-09-17 AI 面试暴露的短板。
> 性质：方向与里程碑层面的规划，不绑定具体周计划；每半年复盘一次，允许被现实修正。

## 〇、一段话版（口述 / 文书通用）

我的职业主线是嵌入式传感系统开发：短期（研究生阶段到 2027 年毕业）聚焦秋招，拿到与传感器、通信、融合算法这条链路匹配的嵌入式软件岗位，同时把 Linux 网络编程、RTOS 和 C++ 这几个短板补到独立工作水平，完成硕士课题与专利收尾；入职后前两年以「从做出来到做可靠」为目标，深入一个行业（半导体设备、机器人或汽车电子），掌握产品级的工程规范和量产思维，成长为能独立负责一个子系统的工程师；三到五年内在多传感器融合与实时系统方向深耕成型，若平台有边缘 AI 机会再切入嵌入式×AI，沉淀专利、技术分享等可见资产，成为团队遇到这类问题首先想到的人；五年之后视积累在系统架构师或技术管理之间选择放大方式。个人成长上，我坚持用数据做决策、每周固定投入长期学习、持续经营知识库与项目复盘，把 AI 辅助开发当效率杠杆但始终由自己负责架构与判断，同时守住健康与职业信誉两条底线，把职业当作三十年的长跑来经营。

---

## 一、主线定位（一句话）

**以嵌入式传感系统为根，做「能独立打通传感器→通信→算法→验证全链路」的工程师；AI 是杠杆，不是主业。**

你的差异化不在单点技术多深，而在于：硬件不怵、C 能写、算法能推（EKF）、上位机能做、验证有方法论（丢包测试/残差分析/烤机）——这条完整链路在应届生里稀缺。规划的核心逻辑就是**把这个稀缺性变成职业资本，再在入职后补上"深"的那竖**（T 型）。

## 二、阶段路线图

### 阶段 0｜现在 → 毕业（2026.09 - 2027.06）｜关键词：落袋 + 交付

**目标**：拿到与主线匹配的嵌入式 offer；硕士课题完整交付；把三个已知短板补到"面试不虚"。

里程碑：
- [ ] **2026 秋招主战场**（当前）：嵌入式软件岗为主投递（半导体设备/机器人/汽车电子三行业并行），面试材料已备齐（docs 01-05），每周复盘一次投递转化
- [ ] **补短板三件套**：Linux socket（写三版 echo server）、FreeRTOS（用它重构毕设调度层）、C++ 语法级过关——这是 AI 面试已暴露的洞，也是春招的保险
- [ ] **课题交付**：microLED 检测系统完成 Mapping 全流程验证，专利推进授权，争取一篇论文
- [ ] **2027 春招**：仅作为秋招结果不理想时的补录窗口，目标提前锁定就不依赖它

不做的事：不碰需要长周期积累才有竞争力的方向（如纯后端、纯算法研究岗）；不在秋招期开新的大项目。

### 阶段 1｜职业起步（2027 - 2029）｜关键词：从做出来 → 做可靠

**目标**：两年内成为团队里"可以独立负责一个子系统"的人。

里程碑：
- [ ] 入职第一年：吃透公司产品的一个完整模块（从原理图/驱动到应用层），把学生期的项目经验"翻译"成产品级经验
- [ ] 补齐学校不会教的三样：工程规范（代码评审/静态检查/单元测试）、量产思维（可测试性、可制造性、故障预案）、跨部门协作（和硬件/测试/项目经理的接口）
- [ ] RTOS 与 Linux 实战达标：能独立定位线上疑难问题（死机/内存/时序类）——把《03 故障排查场景手册》里的方法论在真实产品里走一遍
- [ ] 第二年主动争取一次"从 0 到 1"的小模块 owner 经历（哪怕只是一个传感器驱动或通信协议栈）

不做的事：不频繁跳槽（嵌入式经验高度依赖产品和平台的连续性）；不追求管理岗。

### 阶段 2｜深耕成型（2029 - 2032）｜关键词：选定深挖方向，建立标签

**目标**：成为某一细分方向"团队遇到这个问题会先想到你"的人，并有可见的行业资产。

方向二选一（2029 年前后根据所在行业和兴趣定，不用现在锁死）：
- **主轴 A：实时传感融合与控制系统专家**——深耕多传感器融合（EKF/滤波）、实时系统、运动控制，行业落点在机器人/智能车辆/半导体设备。这是你素材最厚、最顺的路。
- **主轴 B：嵌入式 × AI 工程化**——边缘部署、AI 辅助嵌入式开发工具链（你已有 RAG/LangChain 底子）。赌的是行业趋势，但要求两边都不松手，风险与天花板都更高。

里程碑：
- [ ] 3-5 年内沉淀可见资产：至少一项专利/核心技术文档体系/内部技术分享品牌/开源项目（任选其二）
- [ ] 具备带 2-3 人小组完成一个子系统的能力（不管 title 是否是 lead）
- [ ] 形成个人技术标签：能对外讲清"我是做什么的，做到什么程度"（一篇成体系的技术总结或博客）

不做的事：不两个主轴同时压注（阶段 2 必须收敛）；不为追热点放弃已积累的传感系统主线。

### 阶段 3｜五年后（2032+）｜关键词：放大

届时在两条路里选：**系统架构师/技术专家**（继续深，靠设计能力和疑难问题攻坚立足）或 **技术管理**（带团队，靠项目判断力和培养人立足）。这个选择让阶段 2 的实际感受来回答，现在只需保持两个可能性都开放：架构能力（做大系统的拆分与取舍）和带人经验（mentor 实习生/新人）都要有意识地攒。

## 三、能力成长框架（每半年自查一次）

| 层 | 内容 | 现状 → 阶段 1 目标 |
| --- | --- | --- |
| 硬技术 | C（→C++ 工程级）、RTOS/Linux、驱动与外设、融合算法、基础硬件 | C 良/其余弱 → 全部达到独立工作水平 |
| 工程素养 | 测试设计、Git/CI、文档、调试方法论、规范意识 | 有方法论雏形 → 在产品团队里成型 |
| AI 杠杆 | AI 辅助开发工作流、RAG/Agent 应用、效率工具链 | 已起步且是差异化亮点 → 保持"我负责架构取舍和 review"的深度用法 |
| 软实力 | 技术表达（汇报/答辩）、协作沟通、英语（文档阅读→会议口语） | 表达中上（竞赛答辩经验）→ 英语成为工作语言之一 |
| 知识系统 | Obsidian + CareerOS 持续经营：项目复盘、面试题库、决策记录 | 已成型 → 长期资产，求职/跳槽/晋升的弹药库 |

原则：**硬技术决定下限，工程素养决定被信任程度，AI 杠杆和知识系统决定效率与复利，软实力决定天花板。** 五层不求齐头并进，但每层都不能塌。

## 四、关键决策点（当前默认值 + 触发条件）

1. **行业选择**：默认在 offer 中按"技术链路与毕设/课题的贴合度 > 平台与导师质量 > 薪资"排序。半导体设备（课题对口）/ 机器人与智能硬件（项目对口）/ 汽车电子（稳定性路径）三选一，2027 年签约前定。
2. **城市**：天津（学校与课题在）、南京（本科人脉与实习网络）、深圳/上海（嵌入式岗位密度最高）。跟随行业选择走，不单独作为首要条件。
3. **主轴 A/B**：默认 A（素材最厚）。切换到 B 的触发条件：入职公司本身在做边缘 AI 且有内部转岗机会，或 A 方向行业出现明显收缩。
4. **读博/深造**：默认不读。触发条件：课题做出超出预期的成果且导师有强推荐位——否则工业界对嵌入式更友好。
5. **职业中断风险**：秋招不理想时的兜底顺序：春招 → 扩大岗位半径（硬件测试/测试开发，已有素材支持）→ 实习转正窗口。不在压力下接受与主线完全无关的岗位。

## 五、个人成长原则（非技术，同样"大方向"）

1. **用数据决策，不用情绪**：丢包测试选 100Hz、RMSE 对比选 EKF 参数——这个习惯已经是你的风格，扩展到职业决策（offer 对比、跳槽时机都用量化表）。
2. **长期主义学习**：每周固定投入 3-5 小时在"当前工作用不到但三年后有用"的东西上（现在：Linux/RTOS；三年后：架构与行业认知）。
3. **复利资产意识**：CareerOS、Obsidian 知识库、专利、技术博客——持续把经历"资产化"，而不是干完就丢。
4. **健康与可持续**：秋招和入职前两年是高强度期，守住睡眠底线和每周运动，职业是三十年的长跑。
5. **诚实边界**：不夸大技能（这是你简历材料一贯的纪律），职业信誉是长期最贵的资产。

## 六、复盘机制

- 每半年（3 月 / 9 月）对照本文档做一次复盘：里程碑达成度、决策点是否触发、主线是否需要修正
- 复盘记录写入 CareerVault / docs，保留旧版本——规划的演化史本身就是个人成长的一部分
- 任何阶段：如果连续两次复盘发现方向与现实严重偏离，回到第一节重写主线，而不是硬撑旧规划
