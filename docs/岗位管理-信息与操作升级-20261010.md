# 岗位管理：信息与操作升级

目标：在列表里就能比较岗位、判断进度和处理下一步，完整 JD 与编辑字段按需进入详情。

## 已完成

- 顶部保留搜索、筛选、排序和显示方式；将重复的统计卡、范围标签和导入入口合并。
- 常用阶段直接切换：全部、准备投递、等待回复、面试中、Offer；待核对、重点关注和已结束收进更多视图。
- 每条记录展示公司、岗位、地点、类别、JD 摘录、内推码、关联材料数量、投递阶段与日期、关联日程和真实下一步行动。
- JD 摘录使用已保存原文，优先呈现任职要求和职责，不生成推测内容。仅抓到招聘主页或岗位列表时提示核对，不把公司宣传当作岗位要求。
- 点击 JD 直接打开全文；点击简历、准备或邮件数量直接打开相关详情。
- 阶段可直接修改；「安排下一步」只需填写行动与可选日期，保存后立即更新。
- 搜索支持 JD 关键词；筛选按需展开，阶段、类别与范围仍可组合使用。
- 列表与看板均保留原有记录；紧凑方式可进一步缩短行高。
- 修正搜索、类别、状态和排序的旧事件绑定，避免操作后退回旧版列表。
- 修正简历关联字段，使用实际的 target_opportunity_id，并兼容历史公司与岗位匹配。

## 验证

- 1280 × 720：列表从约 247 像素处开始，首屏约四至五条记录。
- 1024 × 768 和 390 × 844：无横向溢出，小屏按层次排列岗位、JD、进展与行动。
- 隔离副本中验证行动保存、日期校验、阶段变更、JD 关键词搜索、类别筛选、排序、列表与看板切换、关联简历直达。
- 现有 64 项 Python 测试通过；新增只读展示检查覆盖 JD 证据、日期、日程、材料关联、缺失值与无数据修改。
