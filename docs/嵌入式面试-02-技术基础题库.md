## 一、C 语言（嵌入式面试的重中之重）

### 1.1 ⭐ volatile——出现率第一

- 三种场景：① 外设寄存器（硬件随时改）；② 中断服务程序与主程序共享的全局变量；③ 多线程共享变量；
- 作用：告诉编译器不要优化对该变量的访问，每次都从内存重新读写；
- 高分句：「volatile 保证可见性和访问顺序不被优化，但不保证原子性——i++ 在 volatile 下依然不是原子的，原子性要靠关中断或原子指令」；
- 追问：const volatile 能同时用吗？→ 能，如只读状态寄存器（软件不可写、硬件会改）。

### 1.2 ⭐ 内存分区：一个程序从 flash 到 RAM

- text（代码，flash）→ .data（已初始化全局/静态变量，占 flash + RAM，启动时搬运）→ .bss（未初始化全局/静态，启动时清零，不占 flash）→ 堆（malloc 向上）→ 栈（局部变量、函数调用，向下生长）；
- 追问①：「全局未初始化数组占 flash 吗」→ 不占，只在 .bss 清零阶段处理；
- 追问②：「启动文件里 startup 做了什么」→ 搬 .data、清 .bss、SystemInit 时钟、调 main（与 Cortex-M 启动流程联动，见第二节）；
- 追问③：「函数内 static 局部变量在哪」→ .data/.bss（不在栈），生命周期全局、作用域局部。

### 1.3 ⭐ 大小端

- 小端：低字节在低地址（STM32/ARM Cortex-M 默认、x86）；大端：高字节在低地址（网络字节序）；
- 手写判断（背一个）：
```c
int x = 1;
char *p = (char *)&x;
printf(*p ? "little" : "big");
```
- 工程关联：串口协议跨设备传输、传感器数据解析时必须确认字节序（联动的 UWB/IMU 协议解析就是实例）。

### 1.4 ⭐ 结构体对齐与 sizeof

- 规则：① 成员偏移是自身大小的整数倍；② 总大小是最大成员的整数倍；
```c
struct A { char a; int b; char c; };   // 12：a(1)+pad(3)+b(4)+c(1)+pad(3)
struct B { int b; char a; char c; };   // 8
```
- 为什么对齐：CPU 访问效率（部分平台不对齐直接 HardFault）；
- `#pragma pack(1)` / `__attribute__((packed))` 用于通信帧结构体紧凑排布——加分句：「packed 结构体取成员地址可能未对齐，某些平台要用 memcpy 逐字节取」。

### 1.5 ⭐ 指针四件套

- 指针函数 vs 函数指针：`int *f(void)` vs `int (*f)(void)`；函数指针用在回调/中断向量表/状态机跳转表；
- 数组指针 `int (*p)[10]` vs 指针数组 `int *p[10]`；
- 野指针三来源：未初始化、free 后未置 NULL（悬挂指针）、返回局部变量地址；
- 回调机制举例（绑定你项目）：「我的 UART 帧解析完成后通过函数指针回调上层协议处理器，让驱动和应用解耦」。

### 1.6 ⭐ 关键字快问快答

- static：① 修饰局部变量→生命周期全局；② 修饰全局变量/函数→限定本文件可见（内部链接）；
- const：只读；`const char *p`（内容只读）vs `char * const p`（指针本身只读）；
- extern：声明外部符号，典型用在 .h 里；
- typedef vs #define：typedef 是类型别名（编译期类型检查），define 是文本替换（无检查）；
- inline：建议内联，编译器可忽略；宏的副作用（`MAX(i++, j)` 展开出问题）。

### 1.7 位操作（嵌入式日常）

```c
置位：reg |=  (1u << n);
清位：reg &= ~(1u << n);
取反：reg ^=  (1u << n);
判断：if (reg & (1u << n));
```
- 追问：读-改-写与中断竞争→ 对共享寄存器操作要进临界区。

### 1.8 高频笔试题（手写代码）

- 实现 memcpy（考虑内存重叠→memmove；void* 返回值链式调用）；
- 字符串反转、strlen/strcpy 安全版（strncpy 防越界）；
- 判断链表有环（快慢指针）、链表反转；
- 统计一个数二进制中 1 的个数（n &= n-1 循环）；
- 不用临时变量交换两个数（异或）；
- ⭐ 环形缓冲区实现（重点准备，和你项目直接相关）：
```c
typedef struct {
    uint8_t buf[N];
    volatile uint16_t head, tail;  // 单生产者单消费者可不加锁
} ring_t;
int ring_put(ring_t *r, uint8_t d) {
    uint16_t next = (r->head + 1) % N;
    if (next == r->tail) return -1;   // full
    r->buf[r->head] = d; r->head = next; return 0;
}
```
- 讲点：满判断浪费一格 vs 计数器法；单生产者单消费者模型下 volatile head/tail 可无锁（中断写主循环读）——这是你 UART 驱动的实际架构，务必讲得出。

### 1.9 其他高频概念

- 栈溢出原因与检测：大局部数组、深递归；检测→填充 0xA5 模式/栈水位探针/map 文件调整；
- malloc 线程安全性、内存碎片 → 嵌入式倾向静态分配（你 EKF 矩阵静态分配的讲法）；
- sprintf/printf 在 MCU 上的代价（拉入大量库、可重入问题，ISR 中禁用）；
- assertion/debug 宏分层（debug 版 assert，release 版关）。

## 二、ARM Cortex-M（STM32F407 为例）

### 2.1 ⭐ 启动流程（背熟顺序）

上电 → 硬件从 0x00000000（映射到 flash 0x08000000）取向量表 → 取 MSP 初值（向量表第 0 项）→ 取 Reset_Handler 地址（第 1 项）→ 复位例程：搬 .data、清 .bss → SystemInit（时钟/PLL 到 168MHz）→ __libc_init_array → main。
- 追问：「为什么先设 MSP」→ C 运行需要栈，任何函数调用前栈必须就绪；
- 「boot 引脚 BOOT0/BOOT1」→ 决定 0 地址映射到 flash/系统存储器（ISP 串口烧录）/SRAM，联动的「上电不启动」排查场景。

### 2.2 ⭐ HardFault 排查（场景题必考，联动手册场景 1）

- 常见原因：野指针/空指针解引用、未对齐访问、除零（默认不触发，可配置）、栈溢出破坏向量表、跳转到非法地址、fpu 未使能却执行浮点指令；
- 排查手段：① 在 HardFault_Handler 里断点，看压栈的栈帧（PC/LR/xPSR）还原出错指令；② 读 SCB->CFSR/HFSR/BFAR/MMFAR 精确定位总线/存储器错误与出错地址；③ Keil/Cortex-M4 的 Fault Enhancement；④ 结合 map 文件把 PC 地址翻译回函数；
- 主动句：「我项目里遇到过一次栈溢出导致的偶发 HardFault——EKF 里大局部数组，把矩阵改成静态分配并把栈从默认加大后解决，之后我养成用 -fstack-usage 检查的习惯」（对应场景手册 1，可复用）。

### 2.3 中断与 NVIC

- 优先级分组：抢占优先级 vs 子优先级；数值越小优先级越高；
- 中断嵌套规则：高抢占优先级可打断低优先级；
- ⭐ 临界区保护：`__disable_irq()`（PRIMASK）/ BASEPRI 屏蔽低于某优先级/RTOS 临界区；原则「临界区尽量短」；
- ⭐ ISR 编程守则：短小快、不阻塞、不用 printf/malloc、用 xxx_FromISR 接口（RTOS）、数据经环形缓冲交接主循环；
- 中断标志位：手动清除的时机（先清再处理 vs 处理完清，防丢事件）。

### 2.4 外设与系统

- SysTick：1ms 节拍，RTOS 心跳；看门狗 IWDG（独立 LSI）vs WWDG；喂狗策略与「看门狗用于捕获偶发死机」的思路；
- 低功耗模式：Sleep/Stop/Standby 区别与唤醒源（BLE 低功耗的基础）；
- DMA：搬运不占 CPU、配置四要素（源/目的/长度/触发源）、循环模式配 UART 空闲中断收不定长数据（你的标准答案，手册一已强调）；
- map 文件会看什么：段分布、各函数大小、栈堆设置、有没有把大数组误放栈。

## 三、通信协议（UART/I2C/SPI/CAN 概念）

### 3.1 UART

- 帧结构：起始位(1) + 数据(5~9) + 校验 + 停止位(1/1.5/2)；波特率误差容忍约 ±2~3%（累积位偏差）；
- 常见问题排查链（联动场景手册 2）：乱码→波特率/时钟误差；偶发错帧→干扰/地弹→CRC；粘包半包→状态机+CRC；
- RS485/232 差分与共模抑制一句话。

### 3.2 I2C

- 两线开漏 + 上拉，为什么开漏：线与仲裁、多主机、电平兼容；速度 100k/400k；
- 时序：起始/停止/应答；地址 7 位 + R/W；
- ⭐ 仲裁与时钟拉伸一句话概念；
- ⭐ 总线卡死（SDA 被从机拉低）恢复：重新发 9 个 SCL 时钟让从机移完未完成的字节 + STOP；或复位外设/断电重启（联动场景手册 3）；
- 读不到器件的排查顺序：地址对不对（7位 vs 8位写法）→ 上拉/布线 → 示波器看波形 → 逻辑分析仪对照时序。

### 3.3 SPI

- 四根线，主从全双工；CPOL（空闲电平）/CPHA（采样边沿）四种模式——必须能现场推：「模式 0 = CPOL0 空闲低 + CPHA0 第一个边沿（上升沿）采样」；
- 片选作用、多从机挂法；高速信号线等长/串阻一句话；
- 对比 UART/I2C/SPI：速率、线数、主从机制、适用场景一句话各自总结（高频表格题）。

### 3.4 CAN（概念，你没实操过）

- 差分两线、多主仲裁（显性 0 支配、ID 越小优先级越高）、自动重发、错误计数器与 bus-off；
- 数据帧结构：SOF/ID/控制/数据(0~8B)/CRC/ACK/EOF；
- 诚实口径：「UART/BLE 的帧-校验-丢包率-时序验证方法论和 CAN 共通，协议细节我看过 spec，项目上没实操过 CAN 控制器」。

## 四、RTOS 概念层（你没实操，必须概念满分）

- 前后台系统 vs RTOS：确定性、阻塞式编程模型、优先级抢占调度；
- 任务四状态：运行/就绪/阻塞/挂起；
- ⭐ 信号量 vs 互斥锁：互斥锁有优先级继承、用于保护共享资源；二值信号量用于同步/中断通知；计数信号量管理资源池；
- ⭐ 优先级反转：低优先级任务持有锁，高优先级被中优先级挤兑 → 互斥锁的优先级继承缓解（火星探路者案例一句话）；
- 死锁四条件：互斥、持有并等待、不可剥夺、循环等待；预防：统一加锁顺序/超时;
- ⭐ ISR 里为什么不能用普通互斥锁（会阻塞中断）→ 用 xSemaphoreGiveFromISR + 任务通知；
- 任务栈大小怎么定：watermark 探针（uxTaskGetStackHighWaterMark）。

## 五、传感器/算法层（你的主场，确保术语准确）

- ADC 指标：分辨率/参考电压/采样率/INL DNL；采样保持；过采样提信噪比；
- IMU 误差模型：零偏、零偏漂移、随机游走、比例因子误差；标定：静态零偏 + 六面法；
- 卡尔曼家族：KF（线性高斯）→ EKF（雅可比线性化）→ UKF（sigma 点）；互补滤波 = 固定增益近似；
- 滤波器选型：滑动均值（简单延迟）/一阶 IIR（省资源）/FIR（线性相位）；
- 数据级融合 vs 决策级融合；时间同步（硬同步 PPS/软同步时间戳对齐）。
