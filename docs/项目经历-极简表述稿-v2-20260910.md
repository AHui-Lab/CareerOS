# 项目经历极简表述稿 v2（2026-09-10）

> 这版替代 v1 做日常使用。v1 保留了完整证据和边界细节，备查；**平时背、平时用，只看这一份**。
> 改动原因：旧稿每个项目想说的太多，HR 看不出"你做了什么"；今天面试口述乱，根源也是想全讲。

## 三条铁律（这次改动的核心）

1. **简历上每个项目最多 2 条，每条只说一件事。** HR 扫一个项目只有几秒，第一行就必须是"你做了什么"。
2. **口述每个项目只背三句话：这是什么 → 我做了什么 → 结果。说完就停。** HR 追问哪句，才展开哪句。"乱"不是内容不够，是没有刹车。
3. **每句话必须回答"你做了什么、做成没有"。** 技术名词删掉后读不通的句子，整句删掉。

## 边界红线（背下来，面试不踩）

- 当次测试数据 ≠ 长期表现；说数字时带"当次测试"。
- 原型/MVP ≠ 上线产品；没有用户数据就不说用户数、效率提升。
- 专利写"已公布、第二发明人"，不写"已授权"。
- CareerOS 不说"独立开发"；游戏不说"独立设计架构"。
