# 嵌入式重点与训练问答

下列为通用训练题，不是已确认的三一面试真题。先遮住参考回答口述，再对照缺项；底层与应用优先，算法深度取决于 JD。

## C 与 MCU：优先复习

- 指针、数组、栈/堆/静态存储；局部变量生命周期、悬空指针、缓冲区越界。
- volatile 与 const；volatile 不等于原子性，不提供互斥，也不能替代并发同步。
- 位操作、掩码、移位边界；有符号/无符号转换、溢出、协议大小端。
- ISR 内避免阻塞、长耗时处理和无约束动态内存分配。
- UART 接收缓存、DMA/中断概念、帧重同步、超时和错误恢复；这些新学习内容不能自动说成项目已做过。
- 看门狗、复位原因、HardFault 上下文、栈水位、任务心跳。

### 1. 中断和主循环共享状态，volatile 够吗？

参考回答：volatile 能让相关访问按语言实现的 volatile 语义发生，不能保证复合操作原子，也不能保证多字段快照一致。要根据 MCU、访问宽度和并发模型使用短临界区、合适的原子操作或消息传递。若是 DMA，还要考虑平台缓存一致性。先说明平台，再讨论方案。

### 2. 串口帧为什么会解析错？

参考回答：先确定帧结构、长度、大小端、校验和时序，再查接收溢出、丢字节、边界误判及生产/消费并发。解析需支持半帧、粘帧、异常长度、校验错误后的重同步和超时；缓存容量根据峰值速率和处理延迟估算。结合你真实 UART 项目说明实际做过的部分。

### 3. MCU 随机重启怎么查？

参考回答：读复位原因，区分看门狗、掉电/欠压、异常访问及软件复位；记录上次任务状态、错误寄存器、栈与关键事件。复现负载变化、通信压力和长时间运行，再沿电源、栈溢出、越界、死锁等路径缩小范围。先留证据再复位，避免日志丢失。

## 通信：CAN 是当前补课重点

CAN 通用基础：报文广播、标识符参与仲裁、显性/隐性位、错误状态、bus-off、位时序和物理层。经典 CAN 数据帧最多 8 字节，CAN FD 数据段最多 64 字节；帧格式和硬件支持不同。

对于相同帧格式的标准数据帧，较小 ID 通常有更高仲裁优先级；混合标准/扩展帧、数据/远程帧时还需考虑仲裁字段，不把它简化成所有情况只比整数 ID。

高速 CAN 线性总线通常在两端终端匹配；典型端接为两只 120 Ω，并不是每个节点都装 120 Ω。断电且电路允许测量时，CANH/CANL 之间常见约 60 Ω 仅是诊断线索，不能单凭电阻认定通信正常。[TI 官方参考设计](https://www.ti.com/tool/TIDA-01238)

学习 CAN 时还要分清 UART、SPI、I²C、CAN、RS-485：它们的电气层、同步方式、拓扑、可靠性机制和上层协议不同。RS-485 不等于 Modbus，CAN 不等于某个厂家应用协议。

### 4. BMS 与上层通信中断怎么办？

参考回答：检查报文新鲜度/心跳、是否有序号和应用校验；超时后标记通信异常，依据需求限制操作或进入安全状态。不能无限期使用最后一次“允许充电”命令。恢复需验证数据有效、连续通信满足条件，严重故障是否允许自动恢复由需求决定。

### 5. CAN 收不到报文怎么查？

参考回答：由物理层到协议层。查供电、收发器使能/待机、接线、端接和波形；再查波特率、时钟、采样点、控制器错误计数及 bus-off；最后查滤波器、ID 格式、帧类型及发送周期。用 CAN 工具与示波器交叉验证，不先假定只是应用代码问题。

## 调度与 RTOS：理解即可，尚无个人实战证据

理解周期任务、事件任务、优先级、超时、共享资源和最坏执行时间。保护链路的优先级来自安全与时效需求，不能随便规定“所有采样每 10 ms”。

### 6. 互斥量和二值信号量有什么区别？

参考回答：在 FreeRTOS 中，互斥量用于任务间资源互斥，含基本优先级继承，不能从 ISR 使用；二值信号量适合事件同步，需使用合适的 FromISR API。ISR 到任务的通知也可用任务通知机制。具体 API 及允许调用的中断优先级要按移植层配置。[FreeRTOS 互斥量文档](https://freertos.org/Real-time-embedded-RTOS-mutexes.html)、[二值信号量文档](https://freertos.org/Embedded-RTOS-Binary-Semaphores.html)

### 7. 看门狗怎么喂才有意义？

参考回答：不能只在一个一直运行的定时中断中无条件喂狗。由关键任务进展、采集新鲜度和调度状态决定是否满足健康条件；喂狗超时要考虑最坏执行时间。复位前尽量保存诊断线索；复位后的安全启动也需定义。

## BMS 应用题

### 8. 一个电芯温度突然跳高，怎么处理？

参考回答：先保留可能真实故障的快速处理通路，同时检查原始值、量程、传感器开短路、采集链路、时间戳及附近温度。依据需求用滤波、跳变诊断、持续时间和分级响应处理噪声，不能为了“平滑”掩盖真实快速过温。记录原始和处理后数据及触发原因。

### 9. 一个采集从板失联怎么办？

参考回答：标记其数据失效/过期，明确受影响模块与簇，按照架构和需求降额、隔离或停止相关操作，报告故障。不能因为“上次电压正常”就继续视为安全；是否允许其他簇继续工作，要由系统设计支持。

### 10. SOC 不准应该从哪里入手？

参考回答：先核对电流正负号、采样时间和积分单位，查零偏、初值、容量定义、温度/老化补偿，再查模型参数及 OCV 使用条件；用有参考基准的充放电数据对照，分静置、动态工况及不同温度分析误差。先修输入与模型问题，不能只调滤波参数。

### 11. 保护逻辑如何避免反复开关？

参考回答：定义触发和恢复阈值、持续时间、滞回、故障等级与锁存策略，再验证边界抖动。状态机包含故障处置、执行反馈及恢复条件；部分严重故障必须显式清除。快速硬件保护和软件保护分工要清楚。

### 12. 如何验证一个过压保护模块？

参考回答：覆盖正常值、阈值上下边界、持续时间前后、恢复滞回、无效数据、并发故障、动作执行失败和重启后故障保持。先用仿真数据/台架验证逻辑，再按团队规范验证真实硬件。定义输入序列、预期状态与允许响应时限。

### 13. SOC 的 EKF 与你的定位 EKF 有何关系？

参考回答：框架相通，状态、模型、观测和误差来源不同。定位中我实际用 IMU/里程计预测和 UWB 测距更新；SOC 中需要电池模型、电流积分、端电压观测及 OCV-SOC 关系。能迁移算法工程化与异常观测处理经验，但电池参数辨识和量产标定是待补能力。

### 14. 升级时掉电怎么办？

参考回答：设计完整性校验、版本标记及可恢复启动流程，在条件允许时使用双区/回滚；定义升级允许条件、失败恢复和配置兼容策略。校验和/CRC 不能替代真实性验证。不要宣称自己已经做过 Bootloader 或 OTA。

## 手写练习与验收

- 写帧解析函数：输入长度不可信也不越界；覆盖截断、非法长度、错误校验、大小端。
- 写保护状态机：阈值触发、恢复滞回、超时、数据失效、执行失败都有路径。
- 写 SOC 积分：明确单位和正负号，拒绝过期/无效电流，测试恒流和零偏。
- 可选写一个主机侧教学仿真：模拟电压/温度输入与故障状态。标记“学习练习”，不冒充硬件项目或 BMS 量产验证。
