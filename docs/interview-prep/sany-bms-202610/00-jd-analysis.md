## JD 特别需要补的 8 道题

### 如何做驱动模块的需求分析？

明确硬件接口、时序、量程、采样频率、错误码、超时、重试和上下层契约；把“通信正常”“运行稳定”变成可测验收指标。再设计初始化、读写、异常恢复接口及测试方法。

### 怎样让软件可移植？

分离硬件访问、平台服务和业务逻辑；业务模块依赖抽象接口而非具体寄存器/HAL。参数集中管理，使用清晰的类型/单位，隔离编译器与平台差异。用替换驱动或主机桩验证接口边界，不为简单项目过度抽象。

### CPU 忙、丢帧或时序超时怎么定位？

先测输入速率、处理周期与最坏执行时间，检查中断负载、阻塞调用、缓冲峰值和任务优先级。用时间戳/GPIO 翻转或工具采样定位耗时区间，再优化算法、搬运、调度或缓存；优化前后用同一数据与指标复测。

### 单元测试和接口测试怎么区分？

单元测试隔离某个模块逻辑，例如输入电压序列，验证保护状态机；用桩替代硬件读写与时钟。接口测试检查模块间或硬件接口的契约，例如协议编码、超时、错误传播、状态/单位一致性。实车演示不能替代边界测试和回归。

### SPI/I²C 传感器读不到数据怎么查？

先供电、引脚/地址/片选和电平，再初始化与总线波形。SPI 查 CPOL/CPHA、片选时序、速率和字节顺序；I²C 查上拉、地址、ACK、时钟和总线卡死恢复。对照数据手册及可重现波形，不只看 API 返回值。

### C++ 在嵌入式中要注意什么？

理解对象生命周期、RAII、引用、virtual 与资源开销、动态分配的风险以及工具链配置；是否启用异常、RTTI 和堆分配由产品约束决定。你主力语言是 C，C++ 如果没有项目使用，直接说明并展示已理解的基础。

### 与硬件同事怎样高效联调？

给出固件/硬件版本、复现步骤、输入条件、期望/实际波形、日志和初步判断；共同核对接口时序与错误边界。避免仅说“硬件有问题”或“软件没问题”。现场修复后补回归和版本记录。

### 如何回答现场调试或短期出差？

根据真实意愿说明能配合的范围，再了解频率、周期、地点及团队支持。用真实实车或演示经历说明如何准备日志、复现环境和问题清单，不把现场演示夸大成长期售后经验。
