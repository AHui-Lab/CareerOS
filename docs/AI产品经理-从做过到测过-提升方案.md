## 一、诊断：你的问题不是「不会说」，是「没测过」

你在描述里说自己「回答浮于表面、没有底气」。我把你的项目材料、简历和 9 月 7 日顺丰一面面经放在一起对照，得到的结论是：

**这不是表达问题，是证据缺失。面试官追问的每一个「为什么 / 怎么验证 / 效果如何」，在你现有的项目里都没有对应的实物。**

当项目没有测量过，你能说的只有「我觉得应该……」。而「我觉得」在任何一次追问下都会崩——这就是没底气的来源。

### 1.1 面经里的减分信号，几乎逐条命中你的现状

顺丰面经里你自己整理的「❌ 减分信号」，对照你现在的材料：

**流程文档写得再好，也不能替代「我把这套流程跑了一遍，跑出了这些数字」。**

### 1.2 三个断裂

| 断裂 | 表现 | 面试官的追问 | 你现在的处境 |
|---|---|---|---|
| **测量断裂**（最致命） | 所有项目只有功能描述，没有指标 | 「效果怎么衡量？提升了多少？」 | 只能说「感觉变好了」 |

## 二、战略：不要再做新项目，把 1 个项目打透

你现在最不缺的就是项目。**缺的是一个能扛住 20 分钟连环追问的项目。**

一个项目从「作品」变成「案例」，只需要补四样东西：

| 补丁 | 具体内容 | 它能接住的追问 |
|---|---|---|
| **① 真实用户** | 5–10 个真人，用 2–4 周，有使用记录 | 「用户是谁？他们为什么会用？」 |
| **② 失败案例库** | 20–50 条真实 badcase，带分类 | 「它什么时候会失败？」 |
| **③ 前后对比数据** | 改进前 vs 改进后的同一指标 | 「提升了多少？怎么证明？」 |
| **④ 决策记录** | 3–5 条「我放弃了 X 选了 Y，因为…」 | 「为什么不用别的方案？」 |

### 2.1 选哪个项目打透？

**主线：龙虾小助手（wechat_obsdian）。**
理由：
1. 它是 AI PM 面试的**完美载体**——意图识别、工具调用、长期记忆、失败兜底、成本控制、隐私边界、多轮对话。顺丰面经里考的「Agent 架构 + 成本权衡 + 评估」三道题，它全都能用真实数据接住。
2. 微信是**零门槛真实用户入口**。你自己 + 同学/朋友/家人，不需要获客。
3. AI 助手**天天出错**，每一次出错都是你的素材金矿。RAG 知识库你可能一周才用一次，助手是每天在用。
4. 相比 RAG（2026 年校招已高度同质化），助手类产品更能体现「在 AI 不确定性下做产品设计」——这才是 AI PM 的核心能力。

**辅线：RAG 本地知识库。** 它是你最深的 AI 工程证据，顺丰一面已经深挖过它，必须补齐评测。目标不是重写，是**补测量**（详见阶段 0）。

**降为背景：** Godot 游戏（保留为「AI 辅助开发」佐证）、CareerOS（保留为「给自己做产品」佐证）、嵌入式与 miniLED（硬件方向岗位的替换素材，不在 AI PM 主版展开）。

**Ahui-AI-Product-Lab：** 不进简历项目栏，改在「工作方法」里提一句，或在作品集里作为流程展示。

## 三、执行路线图

时间轴基于「秋招进行中」的前提，设计为**边投边补**，每周都有可投递成果。

### 阶段 0（3–5 天）：补上最容易被问死的三个数字

> 目标：这周结束时，简历能新增 3 条硬数据，面试时手里有 3 个可讲的实测故事。
> 原则：**不改功能，只做测量。** 这是投入产出比最高的阶段。

#### 任务 0-1：给 RAG 知识库建 30 题评测集（1.5 天）

这一步在 9 月 4 日的 HR 评审里已经建议过，但至今没做。它是**当前最高杠杆的单项任务**——顺丰一面第 2 题直接考的就是这个。

1. 从你实际投喂的文档里出 30 道题，按五类分布：
   - 直接查找（10 题）：答案在某一处原文里
   - 跨段整合（6 题）：答案需要拼接多个位置
   - 模糊提问（6 题）：用户表述含糊，需要合理推断
   - 库外问题（5 题）：知识库里根本没有答案
   - 冲突材料（3 题）：不同文档说法不一致
2. 每题写：问题、参考答案、证据所在文件与位置。**题目和调参用的样例分开**，否则只证明系统记住了样本。
3. 固定文档集与模型配置，跑两遍：
   - A 组：基础检索（不做阈值过滤、不去重、不扩召回）
   - B 组：当前完整策略
4. 记录四个指标（口径必须先定死，见下方）：
   - **有答案题正确率** = 人工判定达标的题数 / 有答案题数
   - **引用支持率** = 被引用原文实际支持的可核查主张数 / 带引用的可核查主张数（**只看有没有引用不算**）
   - **无依据主张比例** = 无法被知识库证据支持的事实主张数 / 全部可核查主张数
   - **库外问题处理正确率** = 正确拒答或要求补充信息的题数 / 库外题数
5. 同时记录：首字延迟、总耗时、单次调用成本（云端记 token 费用，本地记硬件与推理配置）。

**产出：** `rag-eval/questions.md`、`rag-eval/results-a-b.md`、一张对比表。
**验收：** 能说出「在 30 道题上，有答案题正确率从 A 组 X% 提升到 B 组 Y%」——**样本数和测试条件必须一起说**。

#### 任务 0-2：给龙虾助手建 20 条真实对话记录（1 天）

1. 翻你微信里和助手的历史对话，挑 20 条，按结果分类：
   - 成功执行（任务建对 / 记对账 / 提醒准时）
   - 意图识别错误
   - 工具调用参数错误
   - 该拒绝但没拒绝 / 不该拒绝但拒绝了
   - 记忆没召回 / 召回了错的
   - 延迟过长（>5 秒）用户放弃
2. 每条记录：原始消息、系统动作、最终结果、错误类型、你的修正动作、是否修复、修复版本。
3. 算一个数字：**任务成功率** = 一次表达内正确完成的次数 / 总次数。
4. 挑出 **3 个最有代表性的失败案例**，每个写成「现象 → 定位（意图/工具/记忆/检索哪一层）→ 改法 → 复测结果」。

**产出：** `assistant-eval/badcases.md`（20 条表格 + 3 个深度案例）。
**验收：** 被问「它什么时候会失败」时，能立刻报出失败率和具体类型分布。**能主动讲失败，是面试里极强的可信度信号。**

#### 任务 0-3：算一次全链路成本（0.5 天）

顺丰面经第 3 题明确考「说不清自己项目的单次任务成本」是减分项。

1. 挑助手的一个典型任务（比如「记一笔账」），数清楚：走了几步、调了几次模型、每次输入/输出多少 token。
2. 算三个数：
   - 单次任务 token 成本（不是单次 API 成本，Agent 是多次调用的）
   - 首字延迟（TTFT）与端到端时长
   - 按每天 N 次推算的月度成本
3. 写一段 **50 字的成本权衡结论**：「意图识别用的是 X 模型（便宜快），最终生成用 Y 模型（贵但准）；如果把全链路都换成 Y，成本涨 N 倍但成功率只提升 M%，所以不换。」

**产出：** `assistant-eval/cost.md`。
**验收：** 30 秒内能报出单次任务成本和延迟，并说明理由。

### 阶段 1（第 2–3 周）：真实用户 + 迭代闭环

#### 任务 1-1：找 5–10 个真实用户（先做，其他都依赖它）

具体名单（按难度从低到高）：
- 同门 / 实验室同学（3–5 人）：他们的痛点是**任务提醒、文献/资料查找、报销记账**
- 非技术朋友 / 家人（2–3 人）：他们的表达最不规范，是意图识别最好的测试集
- 如果有微信群，可以小范围放一次

**关键动作：** 每个人先做一次 **10 分钟访谈**，只问三个问题：
1. 你现在记待办 / 记账 / 找资料用什么？
2. 上一次觉得麻烦是什么时候，具体卡在哪？
3. 如果有个微信里能直接说话就搞定的助手，你最先想让它干哪件事？

**产出：** `research/interviews.md`（每人一页，原话优先，不要改写）。
**这一步的价值：** 它一次性解决「用户断裂」。以后所有「为什么这么设计」的回答，源头都是真实用户原话，不再是「我觉得」。

#### 任务 1-2：跑 2–4 周，每周做一次迭代复盘

每周固定做四件事（约 2 小时）：
1. 收集本周所有对话，标注成功/失败，更新 badcase 库
2. 挑 1 个最高频的失败类型，改一版（改提示词 / 改工具 / 改规则 / 改流程，**一次只改一处**）
3. 用评测集复测，记录前后对比
4. 写 200 字周报：本周改了什么、数据怎么变的、下周改什么

**产出：** `weekly/week-N.md` × 3–4 篇。
**这个周报就是面试谈资本身**——「我连续 4 周，每周基于真实使用数据迭代一版，任务成功率从 X 走到 Y」，这句话的分量远超任何功能罗列。

#### 任务 1-3：把 RAG 评测集扩到 50 题并跑第二轮

加入阶段 0 发现的 badcase，验证修改是否真的有效、有没有引入回归。

## 四、简历改造：从「功能清单」到「决策清单」

### 4.1 改造原则

| 现在（功能清单） | 改成（决策清单） |
|---|---|
| 设计并实现了 X 功能 | 用户有 X 问题 → 我判断根因是 Y → 我选了 A 方案而非 B，因为 Z → 验证下来 → 数据 |
| 支持 5 类文档 | 针对 5 类文档设计了差异化切分策略，因为固定长度切分会破坏表格和跨页段落 |
| 提供来源引用 | 用来源引用提供核查入口；实测引用支持率 X%，仍有 Y% 的主张缺乏证据支撑 |
| 支持云端/本地切换 | 云端/本地可切换——因为隐私敏感文档不能出本机；本地推理延迟是云端的 N 倍，这是明确的取舍 |

**一句话原则：每一条都回答「为什么」和「效果如何」，而不只是「是什么」。**

### 4.2 RAG 项目：改造示例

**现在：**
> - 设计扩大召回、相似度阈值过滤与来源去重策略，结合中文文本分块组织检索链路；通过回答来源引用提供原文核查入口。

**改成（补齐阶段 0 数据后填写）：**
> - 针对检索不准的问题，把 badcase 拆成「召回了但生成没用上」和「压根没召回」两类分别定位，据此设计扩大召回 + 相似度阈值过滤 + 来源去重策略。
> - 自建 30 题评测集（含直接查找、跨段整合、模糊提问、库外问题、冲突材料五类），固定文档与模型配置对比基础检索与当前策略：有答案题正确率从 X% 提升至 Y%，库外问题正确拒答率 Z%，引用支持率 W%。
> - 记录首字延迟与单次调用成本；明确该系统在「材料相互冲突 / 已过时」场景下仍会给出不可靠回答，已列为下一阶段改进项。

**为什么这样改更好：**
- 第一句是**定位能力**（面经里说「能否把效果不好拆到检索/生成」是分水岭）
- 第二句是**量化证据**（直接接住第 2 题）
- 第三句是**诚实边界**（主动暴露局限 = 极强可信度，面试官会认为你真做过）

### 4.3 龙虾助手：新增项目范例

> **个人 AI 助手（微信入口 + 确定性工具执行）　2026.07—至今**
> 个人项目 · 独立产品与开发
> - 面向「在微信里用自然语言管理任务、提醒与记账」的场景，按渠道/会话/上下文/理解/策略/执行/反馈/评测八层设计，规定大模型不得越过策略层直接改数据，每个业务动作都有固定工具、权限检查与撤销路径。
> - 建立 20 条真实对话评测集与失败分类（意图识别、工具参数、记忆召回、拒答边界、延迟），实测任务成功率 X%，其中意图识别错误占 Y%；据此改了 Z 处，成功率提升至 W%。
> - 测算单任务全链路成本与延迟：意图识别用小模型、最终生成用旗舰模型的分层路由，相比全链路旗舰模型成本降 N 倍且成功率仅差 M%。
> - 招募 N 位真实用户试用 4 周，每周基于使用数据迭代一版，累计完成 N 个需求的「发现—PRD—验收」闭环。

**注意：** 所有 X/Y/Z/W 必须等真实数据出来才能填。**没做之前，宁可项目篇幅短，也不能编。**

## 五、面试武器库：准备 5 张「故事卡」，不要背答案

顺丰一面的经验总结已经说得很准：**「所有技术问题都要回答出为什么这么做的产品判断。」** 背答案没用，因为追问是无限的。要有的是**可组合的故事**。

每张卡按 `场景 → 我的判断 → 我做了什么 → 数据 → 我后来改了什么` 准备，各写 90 秒版和 3 分钟版。

| 卡片 | 覆盖的追问 | 素材来源 |
|---|---|---|
| **卡 1：一次检索失败的定位与修复** | RAG 效果评估、问题拆解 | 阶段 0 任务 0-1 |
| **卡 2：一次助手犯错的兜底设计** | Agent 失败处理、护栏、安全 | 阶段 0 任务 0-2 |
| **卡 3：一次成本与效果的取舍** | 模型选型、成本-速度-效果三角 | 阶段 0 任务 0-3 |
| **卡 4：一次用户说「我不用这个功能」** | 需求真伪、优先级、砍需求 | 阶段 1 访谈 |
| **卡 5：一次与研发意见不合** | 协作、用数据而非主观说服 | 合越实习的 BLE 对比实验 |

**卡 4 和卡 5 是你目前完全没有、但最容易被问到的。** 卡 5 有现成素材（100 Hz vs 200 Hz 丢包实验）可以直接打磨；卡 4 必须靠阶段 1 的真实访谈。

### 顺丰二面提醒
面经里写了「二面可能结合物流场景」。提前做一次迁移练习：把你的助手拆成「静态知识问答 / 实时数据查询 / 需人工确认的动作」三类，想清楚顺丰场景下哪类任务最值得先做、怎么衡量成功。**这是练习，不能写进简历当顺丰项目经历。**

## 六、每周节奏建议

假设你在秋招期间每天能有 3–4 小时：

| 时间 | 事项 |
|---|---|
| 每天 30 分钟 | 记录当天助手使用中的成功/失败（养成习惯，素材自然积累） |
| 每周一 | 复盘上周 badcase，定本周唯一改进项 |
| 每周中 | 实施改进 + 跑评测集复测 |
| 每周末 | 写 200 字周报，更新简历里的数据 |
| 持续 | 投递 + 面试（每次面完当天复盘，补进题库） |

**最重要的一条：每次面试后 24 小时内，把被问住的问题记下来。** 那就是你下一周要补的东西——比任何通用备考清单都准。
