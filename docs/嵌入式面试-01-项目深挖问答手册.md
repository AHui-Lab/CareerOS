## 一、割草机多传感器融合定位系统（STM32F407）—— 主打项目，必被深挖

### 1.1 三分钟讲述模板（背熟）

> 背景：割草机机器人要在室外草坪做厘米级定位。GPS 米级误差不够，RTK 方案成本高、树下失锁；纯航位推算会累积漂移；视觉方案受光照和草地纹理影响大。所以选了 UWB 测距提供绝对位置基准，IMU + 轮式里程计做高频预测，用 EKF 融合。
>
> 我独立完成：① 硬件选型与接线，UWB 基站×4 + 标签、IMU、轮式里程计接到 STM32F407；② 设计多路 UART 数据协议，DMA + 空闲中断收不定长帧；③ 推导并实现 EKF：状态量为平面位置和速度，预测用 IMU/里程计的运动模型，量测方程是 UWB 距离的非线性方程，求雅可比做线性化；④ 设计基站丢失自适应：检测基站超时/残差异常后降级到最少基站解算甚至纯预测，恢复后重新收敛。
>
> 结果：相比单 UWB 定位，融合后 RMSE 降低 28.86%、MAE 降低 23.14%，真实草坪实车测试达到厘米级；关掉 4 个基站中的 2 个，定位仍持续输出，恢复后误差重新收敛。

### 1.2 方案层问题

**Q: 为什么选 UWB？和其他定位方案比过吗？**
答法要点：
- GPS：单点米级，草坪场景树荫遮挡还会跳变，不满足厘米级；
- RTK-GPS：精度够但贵（基站+天线+订阅），且林下、屋边失锁；
- 视觉/激光 SLAM：草地纹理弱、光照变化大、计算量大，MCU 平台跑不动；
- UWB：10cm 级测距精度、穿透性较好、成本可控；缺点是 NLOS（非视距）和多径会造成测距突跳——这正是我要用融合和残差检测去解决的问题（主动把缺点转化为自己方案设计的引子）。

**Q: UWB 定位原理说一下。**
- 标签发脉冲，基站测量到达时间。TOF 双向测距（TWR）得距离，或 TDOA 到达时间差；
- 已知 ≥3 个基站坐标，用三边定位（三个球面交点）解算位置；实际用 4 个基站，多的一路做最小二乘冗余，提高精度并提供基站故障余量；
- 追问「为什么不是 3 个」：3 球面交两点有二义性+无冗余，4 个能做超定方程最小二乘，还能做残差检验剔坏点。

**Q: 为什么用 EKF，不用 UKF / 粒子滤波 / 简单加权平均？**
- 量测方程（UWB 距离对位置是非线性的 Σ‖p−anchor‖）需要线性化，EKF 用一阶雅可比，计算量小，MCU 上实时性够；
- UKF 精度略好但计算量约 2n+1 个 sigma 点传播，F407 上没必要；
- 粒子滤波能处理多峰分布但我们单峰假设成立，且计算量大；
- 加权平均无法融合运动模型、无法输出不确定度、无法处理不同频率异步量测。

### 1.3 算法层问题（必考）

**Q: 写一下你的 EKF 结构（状态量、预测、更新）。**
- 状态向量 x = [px, py, vx, vy]（如果加了 yaw/速度就按实际说）；
- 预测：匀速/非完整约束运动模型（或者用 IMU 加速度、里程计速度作为控制输入），f(x) 非线性，求雅可比 F；
- 更新：z = 各基站距离，h(x) = ‖p − aᵢ‖，雅可比 H 的每行是单位方向向量（(p−aᵢ)/‖p−aᵢ‖）——这一句说出来非常加分；
- 增益 K = PHᵀ(HPHᵀ+R)⁻¹，更新 x 和 P；
- 追问「P 矩阵物理意义」：状态估计的协方差，预测让它变大（不确定度增加）、量测更新让它变小；工程上看 P 的对角线是否单调增长可以判断滤波器是否「饿死」（长期无量测）。

**Q: IMU 和轮式里程计分别起什么作用？各自的坑？**
- IMU（高频 100~200Hz）：预测步的短时运动信息，姿态参考；坑：零偏和漂移，需要静态零偏校准；
- 轮式里程计（50~100Hz）：速度观测直接约束，抑制 IMU 漂移；坑：打滑和胎压变化导致速度虚报——草坪上打滑是真实问题，可以说「打滑时里程计噪声变大，我把 R 调大或做方差自适应」（有这话就是亮点）。

**Q: 三个传感器频率不一样、时间也不同步，怎么融合？（高频追问）**
- 硬件层：能拉同步线/PPS 最好；实际项目 UART 输出，各自带时间戳；
- 软件层：统一用「到达时间」打时间戳；IMU 高频做预测，UWB 低频（几 Hz~十几 Hz）到达时做更新；两个异步事件之间用最近的状态外推对齐；
- 承认误差：「没有做硬同步，时间误差在 ms 级，对低速割草机（<1m/s）引入厘米以下误差，可接受」——量化承认比含糊其辞加分。

**Q: 基站丢失自适应具体怎么实现？（简历亮点，必被追问）**
- 检测：基站数据超时（如 500ms 无帧）或该基站距离残差（z − h(x)）持续超 3σ；
- 降级策略（做 成状态机 说）：4 基站 → 3 基站最小二乘仍可解算 → 2 基站时仅用里程计/IMU 预测，P 持续增大 → 1 或 0 基站继续纯推算并上报置信度；
- 恢复：基站数据恢复且连续 N 帧残差正常才重新纳入，防止闪回；恢复瞬间 P 较大，量测更新会快速把估计拉回，表现为「误差重新收敛」；
- 追问「关闭 2 个基站是哪 2 个」：如实回答测试配置（比如保留几何位置好的两个对角基站），说明几何精度因子（GDOP）的概念——基站几何越好解算越稳。

**Q: RMSE 降低 28.86% 的真值怎么来的？（数据可信度追问，务必提前准备！）**
- 必须给出可信答案：如「用全站仪/RTK 手段取参考轨迹」「在场地铺标定格线人工标记」「以高精度设备（差分 GPS）轨迹为真值」——选一个你实际采用的口径，绝不能现场编；
- 补充测试方法：同一路径跑 N 圈，单 UWB 与融合两条轨迹对齐后算逐点误差统计。

### 1.4 实现层问题（嵌入式面试官的主场）

**Q: 多路 UART 协议怎么设计的？**
- 帧格式：帧头(2B) + 长度(1B) + 类型(1B) + 序号(2B) + payload + CRC16(2B)；固定前导便于状态机同步；
- 接收：每路 UART 用 DMA 循环模式 + IDLE 空闲中断收不定长帧（这句话是 STM32 收串口的标准高分答案）；
- 解析：状态机（找帧头→收长度→收 body→验 CRC），半包/粘包天然处理；坏帧丢弃并计数（计数器本身就是调试手段）。

**Q: DMA + 空闲中断为什么比逐字节中断好？**
- 逐字节中断在高波特率下 CPU 占用高（115200bps ≈ 11.5k 中断/秒/路，多路直接爆）；
- DMA 搬运零 CPU 占用，IDLE 中断只在一帧结束后触发一次，CPU 只处理完整帧；
- 追问「IDLE 中断里做什么」：读 NDTR 寄存器算本帧长度→从环形缓冲取数据→重启/处理 DMA。

**Q: EKF 在 F407 上的实时性怎么保证？**
- 用 float 不用 double（M4F 有单精度 FPU，double 软件模拟慢一个数量级）；矩阵维度固定，全部静态分配（不用 malloc）；运算在主循环/低优先级任务做，ISR 只搬数据；
- 实测一周期耗时（准备一个数字，如「4 维状态 EKF 一次更新 <1ms @168MHz」）；
- 姿态解算用四元数避免欧拉角奇异。

**Q: 裸机还是 RTOS？为什么？（诚实+展现认知）**
- 实际是裸机前后台 + 状态机 + 定时器节拍；理由：传感器事件驱动、数据流简单，前后台足够且确定性强；
- 加分句：「我了解 FreeRTOS 的任务/队列/信号量模型，知道优先级反转要用互斥量优先级继承解决；这个项目如果上位机通信和运动控制并行需求变复杂，我会迁移到 RTOS」——既诚实又证明有认知。

### 1.5 如果被问「这个项目最大的困难 / 最有成就感的部分」
- 推荐讲「基站丢失自适应」或「第一次实车测试定位发散」（发散原因：里程计打滑 + NLOS 残差互相污染 → 加残差卡方检验和 R 自适应 → 收敛）。与《03-故障排查场景手册》场景 5/6 联动，同一素材两用。

## 二、BLE 通信迁移（合越智能实习）—— 通信协议 + 测试思维主打

### 2.1 两分钟讲述模板

> 做可穿戴动捕手套与 Unity 的数据链路。原来用经典蓝牙 SPP，功耗高、iOS 不支持，我推动迁移到 BLE：定义 GATT 服务与数据协议（帧头+类型+序号+姿态数据+CRC），用 Notify 通道推送。然后用「消息流水号」设计丢包测试：发送端每帧带递增序号，接收端统计序号缺口，测得 50/100Hz 零丢包、200Hz 丢 2.63%，结合动作捕捉所需带宽（人体动作有效带宽 <20Hz，100Hz 采样有余量），最终选定 100Hz。针对手型差异，在接收端做在线归一化和零点校准，配合互补滤波抑制姿态抖动与轴间耦合。

### 2.2 必考问题

**Q: 经典蓝牙和 BLE 的区别？为什么迁移？**
- 经典蓝牙（BR/EDR）：持续连接、SPP 串口剖面、功耗高（数十 mA 级）、iOS 不开放 SPP；
- BLE：GATT 模型、连接事件间隙收发（连接间隔内可休眠）、功耗低一个数量级、手机全平台支持；
- 迁移动机：功耗（可穿戴电池续航）+ iOS 兼容。

**Q: BLE GATT 结构？Notify 和 Indicate 区别？**
- Server/Client、Service → Characteristic → Descriptor 层级；UUID 标识；
- Notify：服务端主动推、无确认、低延迟；Indicate：带确认（客户端回 ACK）、可靠但慢；
- 我用 Notify + 应用层序号/CRC 自己保证可靠性（把可靠性从协议层挪到应用层，是自己设计的亮点）。

**Q: 连接参数是什么？和吞吐/功耗的关系？**
- Connection Interval（7.5ms~4s，每次连接事件才能传数据）、Slave Latency（从机可跳过连接事件）、Supervision Timeout（超时判死链）；
- 间隔小→吞吐高功耗高；间隔大→省电但延迟大。丢包测试就是在找这个平衡点；
- 200Hz 丢包的解释：100Hz×每帧 N 字节已接近该连接间隔下的有效吞吐，200Hz 时发送端队列堆积→溢出丢帧——注意 BLE 链路层本身有重传，应用层看到的「丢」更多是发送端缓冲溢出/背压问题（能分清这两层就是高手答案）。

**Q: 丢包测试怎么设计的？（简历核心亮点，展开讲）**
- 消息流水号：发送端 uint16/32 递增序号嵌入每帧；接收端检查序号连续性，缺口数/总数=丢包率；
- 控制变量：同环境、同距离、每种频率连续测固定时长（如 10 分钟），多次取平均；
- 结果：50/100Hz 0%，200Hz 2.63% → 决策选 100Hz；
- 决策依据补全：香农/奈奎斯特角度，人体运动信号带宽有限，100Hz 采样率对动作捕捉有 5 倍以上裕量；
- 这套「用数据选型而不是拍脑袋」是你在 AI 面试讲「严谨性」的通用素材。

**Q: 数据协议怎么定的？帧格式？**
- 帧头(0x55 0xAA) + 版本/类型 + 长度 + 序号 + payload(四元数/弯曲度，定长，int16 定点压缩) + CRC；
- 定点压缩：浮点×10000 转 int16，省带宽（BLE 单包 20~244 字节 MTU 限制下很关键）；
- 分包与重组：payload 超过 MTU 时拆包、序号+分片索引重组。

**Q: 互补滤波原理？系数怎么调？（和手套项目通用素材）**
- gyro 高频好但漂移，acc 低频准但抖；互补 = α·gyro积分 + (1−α)·acc 修正；
- α 由时间常数 τ 决定（α = τ/(τ+dt)）， τ 取 0.5~2s 量级；调法：静态看抖动、动态看滞后，折中；
- 对比 EKF：互补是固定增益的稳态卡尔曼近似，计算量小，适合低算力姿态环节。

## 三、microLED 晶圆柔性检测系统（研究生课题）—— 机电+采集链路

### 3.1 两分钟讲述模板

> 面向 microLED 晶圆的电学检测：镍纳米线柔性探头接触晶圆电极，我独立完成探头制备与接触验证，设计 16 路电流采集电路与精密位移台集成，实现晶圆定位→扫描→采集→Mapping 全流程，并做了位移平台、相机、被测晶圆三坐标系的标定对齐。成果申请了发明专利（第二发明人，已公布）。坐标系对齐思路：用标准靶标分别测平台系/相机系/探头系间的变换，标定出仿射/刚体变换矩阵，扫描时统一到平台坐标系输出。

### 3.2 常见追问

**Q: 16 路电流采集的技术难点？**
- 通道间一致性（增益/零偏标定，通道间校正矩阵）；微弱电流的噪声（如果是 nA~µA 级：屏蔽、 guarding、RC 滤波、积分式 ADC）；同步 vs 分时采集（分时采样率÷16，够不够看信号带宽）；
- ADC 选型考量：分辨率/量程/采样率/通道数（内部多路复用还是多个 ADC 同步）。

**Q: 位移台怎么控制？怎么防撞？**
- 步进电机开环：回零（限位开关+慢速找零）、软件限位包围硬件限位、速度梯形加减速防丢步；
- 精度相关：细分、丝杆导程、重复定位精度指标，丢步检测可用回零校验或加编码器闭环。

**Q: 坐标系对齐具体怎么做？（手眼标定思路）**
- 标定靶标（棋盘格/圆点阵）放在平台上；相机拍靶标得相机系下特征；平台移动已知位移得平台系度量；解相机-平台变换（AX=XB 手眼标定的简化版）；
- 探头位置用接触通电/打点方式标到平台系；
- 验证：移动到 commanded 位置，实测偏差，残差应在精度指标内。

**Q: 扫描采集的软件架构？（嵌入式视角）**
- 上位机（路径规划、Mapping 渲染）+ 下位机（运动控制+同步采集）；采集与运动同步：位置触发采集（每走 Δd 采一次）比定时采集更贴合 Mapping；
- 数据量大时的流式写盘、断点续扫。

## 四、可穿戴动作捕捉手套 + 计量院实习 —— 传感器前端素材

**Q: 弯曲电阻信号怎么调理？**
- 弯曲电阻（弯曲增大/减小）与定值电阻分压 → 电压随弯曲变化 → RC 低通去高频噪声 → ADC 采样；
- 分压电阻取值 = 传感器中值电阻，灵敏度最优；单电源/轨到轨运放跟随降阻抗。

**Q: 四元数为什么不用欧拉角？**
- 欧拉角万向锁（俯仰 ±90° 时横滚/航向退化）、插值不连续；四元数无奇异、乘法链式更新计算量小、Slerp 插值平滑；
- 追问「四元数初始化」：acc 重力对齐求初始姿态（陀螺零偏静态标定）。

**Q: SVM 怎么用的？特征是什么？**
- 特征：滑动窗口时域统计量（均值/方差/过零率/斜率/弯曲度组合）；核：RBF；留一/交叉验证防过拟合；类别：定义的若干手势；
- 诚实边界：手势类别数、准确率数字按实际准备，别现编。

**Q: 计量院 9 路 IMU 链路的难点？**
- 9 路串口并发（或轮询）、波特率与缓冲区管理、多源时间对齐（统一到达时间戳）、静态零点校准流程（佩戴后保持静止 N 秒采零偏）。
