# 岗位整理与回看

岗位管理默认展示「正在推进」。投递阶段仍保留待处理、准备投递、已投递、面试、Offer 等原有记录，新增独立的整理去向：正在推进、稍后再投、暂不考虑、已结束。没有手动整理过的旧记录沿用原语义：ignored 对应暂不考虑，rejected 对应已结束。Offer 仍在推进视图中。

## 使用

点击「整理岗位」后显示多选框和批量工具条，可配合「最早收集」排序查看收集日期。选择后设置去向，稍后再投可填写回看日期，其他去向无需填写日期。弹窗显示选中公司和岗位、数量，并说明日期和备注会应用于所有选中记录。单条岗位可点击行末「整理」或详情内「整理去向」。

更多视图提供稍后再投、暂不考虑、已结束、全部记录。默认推进视图与各阶段统计排除暂缓及归档记录。暂缓和归档记录保留原始投递阶段、JD、备注、简历、关联邮件及日程；可恢复推进，或在保存后 20 秒内撤销。恢复去向不会把原来的面试记录改成待投递。

回看日期进入总览行动计划；未设置日期则只保留在稍后再投列表。原有下一步行动在暂缓及归档后暂停首页催办，恢复后继续显示。真实手动面试、笔试等日程继续保留和显示，自动生成的截止时间不占用暂缓/归档后的首页重点。

## 实现与验证

SQLite 新增 disposition、revisit_at、disposition_note 三列，空值保留旧状态含义。批量接口 /api/opportunities/organize 使用同一个事务校验和保存，返回变更前快照。客户端提交整理字段的预期值；部分记录不存在或已被其他操作更改时，整批停止，避免部分保存。撤销同样比较整理字段的新值，避免覆盖后续整理。

69 项 Python 测试通过；独立 JavaScript 测试验证视图归类与投递历史不变。数据库副本中验证批量稍后再投、回看日期出现在总览、恢复、撤销和保存后查询；真实页面验证整理入口、最早收集排序、390px 手机工具条和弹窗无横向溢出。测试服务使用单独数据库副本。
